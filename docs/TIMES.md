# Flight-times calculator

`jetlog times`, `jetlog totals` and the `compute_totals` MCP tool compute
logged hours (PIC, co-pilot, dual, night, IFR, cross-country, simulator, and
the EASA FCL.050 columns) from an importable logbook file, or from the
logged-in account's own entries. The calculation runs locally. It is a port
of the Jetlog iOS app's per-entry calculator, and the same numbers are meant
to come out.

## What it computes

For every flight or simulator entry the calculator (`src/times/calculator.ts`)
derives the block time, attributes it to buckets by the pilot's role
(`detailedTimes.ts`), projects the EASA columns (`easa.ts`), and adds night
and IFR time. `aggregator.ts` sums entries into totals, including simulator
device-category routing, trainee and instructed session counts,
cross-country-by-distance and the ATPL credit caps. `CALCULATOR_VERSION`
(`src/times/index.ts`) is 3, the same as the app.

Input comes from one of three adapters, depending on the source:

| Source | Adapter |
| --- | --- |
| A file in an importer format | `importedEntryAdapter.ts` |
| A file in the public payload shape (`csv`, `foreflight`, `jetlog`) | `adapter.ts` |
| The logged-in account (`--profile`) | `apiAdapter.ts`, `apiAircraft.ts` |

Totals for a logged-in account are computed locally from its entries. The
server's own totals endpoint is not used.

### Imported pilot-function columns

The role leads. Columns from another app are honoured only where the Jetlog
app has a matching tile: `pilotInCommand` on the co-pilot seat family (PIC is
carved out of the seat bucket), `coPilot` on CRCP (credited override), `dual`
on SPIC, plus night, IFR and multi-pilot. Every other column (SIC on a PIC
row, partial PIC or SIC, dual on a student, instructor, examiner, the
cross-role relief column) is ignored and the role gets the full block. A zero
in a column counts as no value.

### Aggregation rules

- A flight entry without a calculated block (not flown yet, for example) is
  left out of every total, including `entryCount`.
- A simulator entry is not gated on a block. One without a self-person row is
  still counted, as a trainee session.
- Dates for period filters (`--since`, `--until`, `since`/`until` on
  `compute_totals`) use the derived date, see below.

## Night time

Night is computed in `src/times/night.ts`.

- Minute `i` of the block is night when the sun's elevation at the great-circle
  position at the midpoint of that minute is below -6 degrees.
- All arithmetic is float64 and the result is an integer minute count.
- The count is adaptive (20-minute blocks, bisection where the state changes)
  and always equals evaluating every minute. `nightMinutesBrute` is that
  oracle in the tests. The order of operations is part of the contract, so
  simplifying the arithmetic can change results.
- Off-blocks are minutes after 00:00 UTC of the derived date and may exceed
  1439.
- `night` and `ifr` are clamped to the logged total of the flight. With no
  total they are left as they are. Simulator entries have neither.

## Airport resolution

One resolver (`src/airports/resolver.ts`) turns a code into an airport. The
calculator, the cross-country check, the importers' `canonicalCode` and the
re-import route comparison all use it. A code is looked up as follows:

1. Normalise: trim Unicode White_Space and uppercase (not JS `trim()`, which
   also strips U+FEFF).
2. A user place matching the code in any of its slots.
3. Catalogue ICAO code.
4. Catalogue IATA code.
5. Local code (lowest priority).

A catalogue row or place with only one coordinate axis has no position, never
a (0, 0) placeholder.

Where the catalogue comes from. The package ships no airport data:

- Logged in: the app's airport catalogue (paged, cached per profile under the
  config directory in `cache/`, refreshed by delta) plus the user's own
  places. `times`, `totals`, `import` and the `compute_totals` and
  `import_preview` MCP tools use it.
- Not logged in, or `--offline`: no airports are resolved. A code is its own
  identity (for example `AMS` stays `AMS`), and `resolve` finds nothing.

## Derived date

The derived date is the system date when flight tracking is on for the entry
(`systemDate`, falling back to `date`), otherwise the planned `date`. It feeds
the night calculation and every period filter (`inPeriod`,
`src/times/period.ts`). An entry read from a file has no system layer, so its
derived date is its date.

## Verification

Two shared fixtures pin the calculator to the iOS app's output:

- `test/times/fixtures/times-golden.v2.json` holds 284 cases, generated by
  running the app's calculator. `test/times/golden.test.ts` checks every case
  exactly: `night`, `detailedTimes`, `easaTimesSigned`, `easaTimesUnsigned`,
  `resolved` (the resolver's output for the derived from/to), `derivedDate`
  and `inPeriod`. The cases cover roles, manual overrides, imported-column
  policy, bulk and simulator entries, aircraft classification, IFR, overnight
  wrap, polar and date-line routes, a latitude/duration grid, 32 airport
  resolution cases and 6 derived-date cases. Each case carries its own
  catalogue and user places. The test also asserts that the fixture's
  `calculatorVersion` equals `CALCULATOR_VERSION`.
- `test/times/fixtures/night-v2-vectors.json` holds 2150 night vectors.
  `test/times/nightV2.test.ts` reproduces all of them exactly.

`KNOWN_NIGHT_MISMATCHES` in `golden.test.ts` is empty and should stay empty.
Night is float64 with an integer result on every platform, so a mismatch
means a real deviation.

These tests exercise the calculator and resolver. The adapters, aggregator,
role-code tables and file glue have their own unit tests in `test/times/`.

## Known limitations

- File path, no aircraft types. `jetlog times` and `jetlog totals <file>` have
  no offline aircraft-type database, so single/multi-engine and
  single/multi-pilot classification is empty for files. The logged-in
  `--profile` path classifies aircraft through the account's aircraft and the
  app's aircraft-type catalogue, resolving the type from the system or user
  ICAO code with no fallback (bulk entries by ICAO code, so a registration
  such as `MD11` is never read as a type).
- Simulator times in the public payload. The payload has no start or end time
  for simulator sessions, so the payload adapter approximates with
  `off_blocks` and `on_blocks`. The importer adapter and the logged-in
  adapter use real start and end times.
- Simulator device category, logged in. The read API has no FNPT, FTD or FFS
  category per session, so `jetlog totals --profile` reports
  `fnptSessionMinutes` and `nonCreditableSimSessionMinutes` as 0. From a file
  they are filled.
- ATPL progress. The CRCP, FNPT and synthetic caps are applied
  (`applyAtplCaps`), but the "best of three routes" PIC-pillar calculation of
  the app's ATPL progress screen is not implemented.
- Cruise relief credit sums the stored `cruiseReliefCoPilotCredited` and does
  not fall back to the Part-FCL formula for legacy rows without one. Entries
  computed here always have the value.
- Without a login (or with `--offline`) there are no airport positions, so
  night time and cross-country by distance are not computed. `times` and
  `totals` on a file print one `note:` line on stderr, and the `compute_totals`
  MCP tool returns it in `notes`. The night column is blank in the table and
  the totals summary has no Night line. In `--json` output the night total is
  0, which means "not computed" there.
  Importers also no longer turn an IATA code into ICAO without a login.
- A tracked entry (`update_flight_data`) logs its whole block as IFR even when
  its `ifr` flag is false. This follows the app.
